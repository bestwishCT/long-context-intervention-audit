032: 4.2 Effect of Query-Aware Contextualization
033: Our multi-document QA and key-value retrieval
034: experiments place the query (i.e., question to an-
035: swer or key to retrieve) after the data to process
036: (i.e., the documents or the key-value pairs). As
037: a result, decoder-only models cannot attend to
038: query tokens when contextualizing documents or
039: key-value pairs, since the query only appears at
040: the end of the prompt and decoder-only models
041: can only attend to prior tokens at each timestep.
042: In contrast, encoder-decoder models (which seem
043: more robust to changes in the position of rele-
044: vant information;§4.1) use a bidirectional encoder
045: to contextualize input contexts—can we use
046: this observation to improve decoder-only mod-
047: els by placing the query before and after the
048: data, enabling query-aware contextualization of
049: documents (or key-value pairs)?
050: We find that query-aware contextualization dra-
051: matically improves performance on the key-value
052: retrieval task—all models achieve near-perfect
053: performance on the 75, 140, and 300 key-value
054: pair settings. For example, GPT-3.5-Turbo (16K)
055: with query-aware contextualization achieves per-
056: fect performance when evaluated with 300
057: key-value pairs.
058: In contrast, without query-aware contextual-
059: ization, the worst-case performance is 45.6%
060: (Figure 7). Despite the significant impact on
061: key-value retrieval performance, query-aware
062: contextualization minimally affects performance
063: trends in the multi-document question answering
064: task (Figure 9); it slightly improves performance
065: when the relevant information is located at the
066: very beginning of the input context, but slightly
067: decreases performance in other settings.
